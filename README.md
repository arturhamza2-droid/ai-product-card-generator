# AI-помощник для подготовки товарных описаний

Прототип сервиса: по JSON с данными о контрольно-измерительном приборе (название, производитель,
характеристики, описание) готовит **черновик карточки товара** для B2B-магазина:

- SEO-заголовок (до 70 символов);
- SEO-описание (800–1200 символов);
- структурированный список ключевых характеристик;
- 3–5 поисковых запросов;
- блок для менеджера (кому подходит, какие задачи решает, на что обратить внимание);
- раздел «Что проверить»: чего не хватает во входных данных и что вызвало сомнения.

Главный принцип: **модель пишет только тексты, а характеристики копирует код** — дословно из ваших
данных. Всё, что можно проверить кодом (длины, количество запросов, числа, которых нет во входных
данных, слова про сертификаты, стандарты и гарантии без опоры на данные), проверяется кодом. Подробности — в [DECISIONS.md](DECISIONS.md).

## Установка (Windows, macOS, Linux)

Нужен Python 3.10+.

```bash
python -m venv .venv
```

Активируйте окружение:

- Windows (PowerShell): `.venv\Scripts\Activate.ps1`
- Windows (cmd): `.venv\Scripts\activate.bat`
- macOS / Linux: `source .venv/bin/activate`

```bash
pip install -r requirements.txt
```

## Настройка ключа

1. Скопируйте `.env.example` в `.env`.
2. Откройте `.env` и впишите значения справа от `=`:

```
LLM_BASE_URL=адрес OpenAI-совместимого API (например https://api.example.com/v1)
LLM_API_KEY=ваш ключ
LLM_MODEL=название модели (например claude-sonnet-5.5)
```

Файл `.env` добавлен в `.gitignore` и в репозиторий не попадает. Ключа в коде нет. Подойдёт любой
API, совместимый с протоколом OpenAI Chat Completions (OpenAI, OpenRouter, «туннели», локальные
серверы вроде Ollama/vLLM).

## Запуск

**Командная строка** (основной способ):

```bash
python -m app.cli examples/input/pd100-di0-6-115-0-5.json
python -m app.cli examples/input/pd100-di0-6-115-0-5.json examples/input/si8-n-s.json -o examples/output
```

- `-o папка` сохраняет рядом `.md` (удобно копировать в CMS) и `.json`.
- `--format md|json|both` — что печатать на экран.
- `--model gpt-5.5` — временно взять другую модель вместо указанной в `.env` (для сравнения).
- Данные можно передать через stdin: `cat product.json | python -m app.cli -`.
- Коды выхода: `0` — всё хорошо; `1` — ошибка входных данных или API; `2` — не заданы настройки;
  `3` — карточка получена, но часть автопроверок не пройдена (нужна ручная правка).

**Веб-форма:**

```bash
python -m uvicorn app.web:app
```

Откройте http://127.0.0.1:8000, вставьте JSON, нажмите «Сформировать карточку». Результат
показывается в двух блоках (Markdown и JSON) с кнопками «Копировать».

## Формат входных данных

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {"диапазон измерений": "0–1,6 МПа", "класс точности": "1,5"},
  "description": "Прибор предназначен для измерения избыточного давления..."
}
```

Обязательно только `name`. Остальные поля могут быть пустыми: сервис не будет их «досочинять», а
укажет в разделе «Что проверить», чего не хватает. Если нет ни характеристик, ни содержательного
описания, модель не вызывается, а сервис сообщает, что данных недостаточно.

## Примеры результата

Лежат в [examples/output](examples/output) (рядом `.md` и `.json`):

| Товар | Вход | Результат |
|---|---|---|
| ОВЕН ПД100-ДИ0,6-115-0,5 (датчик давления) | [json](examples/input/pd100-di0-6-115-0-5.json) | [md](examples/output/pd100-di0-6-115-0-5.md) · [json](examples/output/pd100-di0-6-115-0-5.json) |
| ОВЕН СИ8-Н.С (счётчик импульсов) | [json](examples/input/si8-n-s.json) | [md](examples/output/si8-n-s.md) · [json](examples/output/si8-n-s.json) |
| Демо с неполными данными | [json](examples/input/_demo-incomplete.json) | [md](examples/output/_demo-incomplete.md) |

Товары выбраны из выгрузки `feed.xml` магазина «Союз-Прибор». В самой выгрузке нет характеристик и
описаний (только название, бренд, артикул, цена), поэтому характеристики и описание взяты со страниц
товаров скриптом [scripts/fetch_product.py](scripts/fetch_product.py):

```bash
python scripts/fetch_product.py https://www.souz-pribor.ru/product/si8-n-s/ --manufacturer "ОВЕН" -o examples/input/si8-n-s.json
```

## Структура проекта

```
app/config.py    настройки из .env
app/product.py   разбор и проверка входного JSON
app/specs.py     ключевые характеристики (собирает код, не модель)
app/prompts.py   системный промпт и сообщения для повторной попытки
app/llm.py       обёртка над API: ошибки, повторы, разбор JSON
app/checks.py    проверка ответа: длины, число запросов, «лишние» числа
app/service.py   сценарий: проверка → модель → проверка ответа → повтор
app/render.py    вывод в Markdown и JSON
app/cli.py       командная строка        app/web.py   веб-форма
scripts/fetch_product.py  подготовка входных JSON со страниц магазина
examples/        входные данные и готовые результаты
tests/           тесты
```

Использованные промпты, принятые решения, ограничения и план улучшений — в
[DECISIONS.md](DECISIONS.md).
